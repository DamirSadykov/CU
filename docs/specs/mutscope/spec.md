# Спека: mutation testing по области изменения

## contract — Вход и результат

part: требования

- `mutscope` принимает git diff и рассматривает изменённые строки JS/TS/Vue и
  Rust как область мутации. По умолчанию это рабочий diff относительно `HEAD`;
  допустимы две ревизии, staged diff и записанный diff.
- Один вызов создаёт один mutation-testing-elements JSON. Отчёты нескольких
  изменённых файлов объединяются с перенумерацией test id. Поле
  `mutscope.changes` сохраняет исходные файлы и выбранный адаптер.
- Диапазон лестницы задаётся `--from 0..3` и `--to 0..3`. `StringLiteral`
  исключён по умолчанию; `--keep-strings` включает его.

## ladder — Вывод тестов и подъём

part: устройство

- Уровень 0 — одноимённый соседний тест; в Rust также одноимённый integration
  test и inline `mod tests` изменённого файла.
- Уровень 1 — тесты, достигающие файла по статическому графу относительных
  JS/TS imports, либо Rust integration tests со ссылкой на модуль.
- Уровень 2 — тесты каталога слоя, либо тесты крейта. Уровень 3 — весь набор.
  Каждый уровень содержит только тесты, которых не было ниже.
- Каждый мутант стартует на нижнем выбранном непустом уровне. `Killed`
  прекращает его прогон; `Survived` и `NoCoverage` поднимаются дальше.
  Stryker получает точную позицию мутанта, cargo-mutants — точное имя.
- Все тесты уровня успевают выполниться: Stryker работает с `disableBail`,
  cargo-mutants — с `--no-fail-fast`. Поэтому `killedBy` не сводится к первому
  случайно упавшему тесту.

## quarantine — Нестабильные JS-тесты

part: инварианты

- Перед mutation run JS-тест проверяется в пуле `threads` с одним worker.
  Падение исключает файл из уровня с причиной `threads`; результат кэшируется
  по хэшу содержимого.
- Тест, упавший в initial dry run Stryker, сопоставляется с файлом по названиям
  suite/test, получает причину `dryRun`, исключается, и уровень повторяется.
- Если после карантина уровень пуст, он пропускается. Если пусты все выбранные
  уровни, запуск завершается ошибкой, а не пустым успешным отчётом.

## report — Наблюдаемость

part: требования

- Мутант хранит последний достигнутый `level` и `durationMsByLevel`.
  `mutscope.levels` хранит длительность, тесты и число мутантов по запускам;
  `mutscope.quarantined` — исключения; `mutscope.traces` — фазы Stryker,
  dry-run, планы, таймауты и накладные расходы.
- Человеческая сводка перечисляет объединение тестов из `killedBy`, отдельно
  `Survived` (код исполнялся, поведение не проверяется) и `NoCoverage` (код вне
  тестов). Источником классификации служит статус адаптера, а не наличие имён
  тестов: cargo-mutants не раскрывает покрывающие тесты выжившего мутанта.

## limits — Границы достоверности

part: инварианты

- Граф JS/TS не разрешает aliases, package imports и вычисляемые specifiers.
- Покрытие дочернего Node-процесса зависит от унаследованных `NODE_OPTIONS` и
  `__STRYKER_ACTIVE_MUTANT__`. Дочерний процесс с полностью заменённым `env` и
  любой не-Node процесс не участвуют в coverageAnalysis.
- cargo-mutants восстанавливает `killedBy` из per-mutant логов; точные
  `coveredBy` для выживших недоступны.
